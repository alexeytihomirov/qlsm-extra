# Demo stream: hold the full snapshot after a resync until the client acknowledges it

## Цель

После рестарта хаба, обрыва связи или потери блоков живой поток POV восстанавливается сразу, а не отрезками по 10 с: плагин `demo_stream_resync_hold` держит `deltaMessage = -1` у клиента несколько кадров подряд, пока клиент не подтвердит полный снапшот. Доказано замером на `qlds@27960` (germany) тем же способом, что и базовый замер в `ql-stats-hub-0009`.

## Контекст

Базовый замер 2026-10-12 (`ql-stats-hub-0009`): после рестарта хаба из 2251 блока за 60 с только 656 со снапшотом, четыре отрезка по ~400 блоков без картинки; второй рестарт - один отрезок 208 блоков. Причина - открытый пункт 1 плана `docs/superpowers/plans/2026-10-12-live-stream-synthetic-keyframe.md`: движок (`_build/minqlxtended-fork/src/features/stream.c:1703-1734`) ставит `deltaMessage = -1` на один кадр, следующие снапшоты - дельты от сообщений, которых хаб не видел. Оператор не хочет правку движка, просил плагин.

Факты по исходникам форка (ветка `demo-match-capture`, HEAD `48ea98f`; развёрнутая сборка `16f09a3` не предок HEAD, но отличается от него только файлом `docs/superpowers/plans/2026-10-11-stream-keyframe.md`):

- `minqlxtended.Client(n)` - вид на `client_t`, поля из `src/python/engine_fields.h:607-634`: `delta_message` (:627), `message_acknowledge` (:613), `state`, `netchan.outgoing_sequence` (:596). Запись - простое присваивание в память движка (`src/python/python_objects.c:708-731`, макрос `QLX_GETSET_INT`; таблица атрибутов `:2262`).
- Порядок кадра: `My_G_RunFrame` (`src/server/hooks.c:681`) вызывает `FrameDispatcher()` (:694, событие `frame` плагинов, `python/minqlxtended/_handlers.py:218`), потом `Stream_Frame()` (:705), потом `G_RunFrame` (:709). Движок сам ставит `-1` в `Stream_Frame` и этот снапшот уходит полным (измерено в `ql-stats-hub-0009`), значит запись из хука `frame`, который идёт в том же месте кадра чуть раньше, тоже доживает до отправки. То, что пакеты клиентов читаются до `G_RunFrame`, а снапшоты шлются после - порядок id Tech 3, в исходниках форка его нет (движок закрыт).
- `-1`, выставленный самим движком, плагину НЕ виден: он ставится после хука и затирается следующим пакетом клиента до следующего хука. Поэтому слежение за `delta_message == -1` как триггер не годится.
- Триггер - `minqlxtended.stream_status()` (`src/python/python_embed.c:2552`): счётчик `resyncs` и по слотам `active` / `resyncing` / `gen`. Флаг `resyncing` (`stream_resync_pending`) снимается только когда полный блок ушёл в поток (`stream.c:1355-1358`).
- Из кода, вживую не проверено: пока связь с хабом лежит, движок форсит полный снапшот КАЖДЫЙ кадр каждому открытому POV (`stream_note_drop` ставит флаг, `stream.c:1128`; `stream_force_resyncs` не смотрит на связь, :1703-1734; флаг не снимается, потому что при упавшей связи `Stream_Block` не вызывается, :1330-1333). Отдельная находка для движка.

## Как проверить

Нужен игрок на `sD test server` (germany, 27960) в разминке. Из корня рабочего дерева `qlsm-extra`, Git Bash, python с пакетом `websockets`. Адреса скрипт берёт из переменных `QL_SSH_KEY`, `QL_GAME_HOST`, `QL_HUB_SSH`, `QL_HUB_HTTP` (значения нашей установки - в `skills/qlsm-dev/reference/deploy-and-hosts.md` монорепозитория), без них не запускается:

1. Плагин должен быть загружен: rcon `qlx !resynchold` отвечает строкой `demo_stream_resync_hold 1.2: ...` (на сервере пока лежит 1.1). Если молчит - положить `demo_stream_resync_hold.py` в `/home/ql/qlds-27960/minqlxtended-plugins/` (ql:ql 644) и `qlx !load demo_stream_resync_hold`.
2. `QL_CONFIRM=1 bash tests/manual/demo_stream_resync_hold_measure.sh on` - скрипт сам проверит, что на хабе нет POV других серверов, что есть свой POV, `PRE_GAME` и плагин (иначе выйдет с кодом 3-7, ничего не рестартуя), рестартует хаб, в конце вернёт cvar к прежнему значению и 60 с пишет все слоты. Ожидаемо для каждого слота: `without_snapshot=0 runs_of_20_or_more=0 []`, `no decodable snapshot lines since the restart: 0`; в журнале плагина после строки `link up` по одной строке `hold started (flag)` на слот и `hold ended: acknowledged ..., N full snapshots forced` с N от 1 до 3.
3. `QL_CONFIRM=1 bash tests/manual/demo_stream_resync_hold_measure.sh off` (не раньше чем через минуту) - без плагина результат случайный: либо 0, либо сотни блоков без снапшота (в базе отрезки по ~400). Сравнивать по нескольким прогонам.
4. Весь вывод каждого прогона лежит в `/tmp/resync-hold-measure/<stamp>-<mode>.log`, дампы рядом.
5. В обычной работе: `qlx !resynchold` - `acknowledged` равен `holds`, `hit the cap 0`; `qlx !resynchold log` - последние 64 события.
6. Убрать с сервера: rcon `qlx !unload demo_stream_resync_hold`, затем `rm /home/ql/qlds-27960/minqlxtended-plugins/demo_stream_resync_hold.py`.
